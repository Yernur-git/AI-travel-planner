## D01 — Подготовка до кода

Статус: выполненная ранее документальная подготовка. Тогда создавались только план, правила агента, решения, формат обмена и папка логов. Новый запрос разрешает общую основу приложения; см. D09. Историческое ограничение «без кода» больше не описывает текущую задачу.

## D02 — Границы MVP

Статус: требование пользователя и proposal. Алматы, 1–3 дня, даты, интересы, общий бюджет в KZT; маршрут по дням с расписанием, источниками и оценкой расходов. Питание, местный транспорт и билеты включены; жильё и дорога до Алматы исключены по proposal. Нет бронирования и оплаты. Карта и погода отложены как дополнительные цели.

Предложено: один путешественник, русский язык, отсутствие аккаунтов и БД. Согласовать перед кодом; не выдавать эти упрощения за уже подтверждённые участниками.

## D03 — Простой Python-проект

Статус: основа реализована на Python 3.11 + Streamlit, Pydantic для форматов и pytest для проверок. Первый JSON-каталог и поиск добавлены Ернуром, см. D10. Без отдельного API-сервера, vector store и агентного фреймворка в MVP.

Причина: двум участникам проще интегрировать Python-модули и запускать локально за пять учебных недель. Альтернатива с отдельным frontend/backend добавит контракт сети и два окружения; пересмотреть только при конкретной необходимости. Зависимости основы установлены в `.venv` на Windows/Python 3.11.9; проверенные прямые версии закреплены в requirements. Машина второго участника ещё не проверена.

Справка: [официальная установка Streamlit](https://docs.streamlit.io/get-started/installation). Чтение документации не является проверкой установки на машинах участников.

## D05 — Каталог и ограниченный AI-цикл

Статус: proposal + предложенная детализация. Ернур собирает примерно 25 мест из публичных источников, фиксирует URL, поддерживаемые факты и реальные даты проверки. На 16 ноября 2026 собраны первые 5 мест и 13 источников с явными пробелами/расхождениями; загрузка и поиск реализованы (D10). Остальной каталог остаётся открытым.

AI выбирает ID из каталога, составляет расписание, получает ошибки валидаторов и пытается исправить результат. Предлагается максимум три генерации на запрос (первый ответ + две коррекции); подтвердить с учётом лимитов. Это содержательная генерация и пересмотр маршрута, а не свободный чат. При недоступном API выводить ошибку; baseline допустим только как явно обозначенный режим сравнения, не как успешный AI-вызов.

Проверку бюджета реализует Рахат; расписание закреплено за Ернуром. Неизвестные цены дают частичный расчёт, неизвестные часы не дают статуса «проверено». Форматы реализованы в `src/contracts/models.py`; проверки ссылок реестров реализованы в каталоге, расписание и расчётный модуль пока отсутствуют.

В `docs/CONTRACT.md` предложено для будущей версии разрешить позицию, связанную только с датой. Модели не менялись; предложение не означает согласование участниками.
