## Модель, тариф и подключение

Выбрана и проверена вызовом `gemini-3.5-flash-lite`. В [официальной карточке](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite) указан этот ID, а [таблица Standard](https://aistudio.google.com/docs/pricing#gemini-3.5-flash-lite) указывает бесплатные входные и выходные токены в Free tier. Gemini 2.5 Flash ограничен для существующих пользователей и объявлен устаревшим; для нового подключения он не выбран. [Список моделей](https://aistudio.google.com/docs/models) также перечисляет Gemini 4 Hydrogen, Gemini 3.8 Flash, Gemini 3.6 Flash и Gemini 3.1 Flash-Lite; наличие в списке само по себе не доказывает бесплатность или доступ аккаунту.

[Официальный Python SDK](https://aistudio.google.com/docs/get-started) называется `google-genai`; текущий quickstart использует `genai.Client` и `client.interactions.create`. Установлены и закреплены `google-genai==3.6.1`, `python-dotenv==1.2.4`. Реальный вызов использует Interactions API, `store=false`, JSON Schema существующего PlanDraft: [структурированный вывод](https://aistudio.google.com/docs/structured-output). Сохранение на сервере отключено для состояния беседы; это не отменяет условия обработки данных Free tier.

Числовые RPM/TPM/RPD не фиксируются по старым примерам: [активные лимиты](https://aistudio.google.com/docs/rate-limits) зависят от проекта и показываются в AI Studio. Часть проектов требует проверки для Free tier. Free tier может использовать входные и выходные данные для улучшения продуктов Google, согласно странице тарифов. В будущий запрос следует передавать только TripRequest и необходимый каталог без секретов и персональных данных.

Для этой задачи использовать только проект Free без подключённого billing. Не нажимать Set up billing / Upgrade, не подключать карту, платные инструменты, поиск или карты. Модель с бесплатным тарифом может тарифицироваться в платном проекте; имя модели само по себе не гарантирует нулевые расходы. Пользователь подтвердил Free без billing в чате; код не проверяет billing через Google Cloud и не меняет его. Разрешена только модель `gemini-3.5-flash-lite`, без автоматической замены.

## Локальное сохранение ключа

1. Открыть [Google AI Studio API Keys](https://aistudio.google.com/apikey), войти в свой аккаунт и создать ключ в проекте Free. Для нового аккаунта проект/ключ могут быть созданы автоматически. При необходимости выполнить проверку проекта без подключения billing. [Официальные инструкции](https://aistudio.google.com/docs/api-key).
2. В PowerShell из корня проекта создать локальный файл, только если его ещё нет:

   ```powershell
   if (!(Test-Path -LiteralPath .env)) { Copy-Item .env.example .env }
   notepad .env
   ```

3. В редакторе заполнить значение после `GEMINI_API_KEY=` и указать `GEMINI_MODEL=gemini-3.5-flash-lite`. Сохранить и закрыть. Ключ не вводить в командную строку, не отправлять в чат, не показывать через Get-Content, скриншоты или логи. `.env.example` оставить с пустыми значениями.
4. Проверить игнорирование без чтения содержимого:

   ```powershell
   git check-ignore .env
   git ls-files -- .env
   ```

   Первая команда должна показать `.env`, вторая не должна ничего вывести. Если файл уже отслеживается, одного `.gitignore` недостаточно; не добавлять секрет до устранения отслеживания.
5. Сообщить агенту только о готовности файла и тарифе Free без billing. Сам ключ остаётся локально. Провайдер должен передавать его только сервису Gemini для аутентификации.

Демо и каталог `.env` не загружают. Отдельный CLI читает `.env` из корня проекта через python-dotenv, без интерполяции; переменные процесса имеют приоритет. Ключ скрыт в repr настроек и не передаётся в prompt. Streamlit остаётся демо.

## Реализация и ограничения

- `src/ai/gemini.py`: настройки, prompt, вызов, проверки. `src/ai/__main__.py`: отдельный CLI. app.py, UI, бюджет Рахата и общие модели не изменены.
- Проверяются существующие TripRequest/PlanDraft, точные даты, уникальные ID, существование и связь Place/Source/CostBasis, наличие источника названия, связь интересов, порядок без пересечений, минимальная длительность, известные часы и исключения, отсутствие повторов мест, соседство переходов. У каждого дня нужен визит, максимум 12 активностей.
- Нет реестра оценок переходов: их длительность только null, method=unknown; придуманные оценки запрещены. Неизвестные часы сохраняются неизвестными. Полный статус расписания остаётся unknown, даже если базовые проверки прошли. Это не полный модуль `src/schedule/` и не гарантия географии, касс или будущей доступности.
- Поля цен/URL/часов в ответе запрещены схемой. Свободные reason и assumptions модели полностью заменяются контролируемым текстом; это обрабатывается до вывода. Названия, цены, часы и URL в диагностике подставляются из каталога. Неизвестные расходы не становятся нулём; бюджет не считается.
- Вывод CLI является локальной диагностической оболочкой с PlanDraft и существующим ResultMetadata, а не новым общим форматом или TripResult. `mode=ai`, модель, версии и число генераций фиксируются кодом. При ошибке draft=null, код возврата 1; демо не подставляется.
- По умолчанию одна генерация, опционально 2–3. Повторяется только невалидный ответ; квота, доступ и сетевые ошибки прекращают запуск сразу. Внутренние повторы SDK отключены (`attempts=1`); таймаут одного обращения 45 секунд. Ответ ограничен 6000 токенов и 100000 символов до разбора. Блокировка/обрезанный ответ также не принимаются.
- Отдельные безопасные коды для отсутствия ключа, неподдержанной модели, отказа доступа, квоты, недоступной модели/сервиса, отклонённого запроса и невалидного ответа. Сырые SDK-исключения и ответы не печатаются. Повторная попытка не воспроизводит недоверенный ответ в prompt.

Изменение контракта `1.1-draft` для диагностики PlanDraft не требуется. Интеграция в полноценный TripResult с бюджетом и UI остаётся отдельной совместной работой.

## Ручной запуск

Из корня проекта после локальной настройки Free:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m src.ai --request data/gemini-request.example.json
.\.venv\Scripts\python.exe -m src.ai --request data/gemini-request.example.json --max-attempts 2
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

Пример запроса использует 26 ноября 2026, culture/history, лимит 15000 KZT; это проверочный вход, не предпочтения пользователя. Для своей проверки скопировать JSON в `output/`, указать нужные 1–3 дня, бюджет и интересы и передать путь через `--request`. Лимит передаётся модели как вход, соблюдение бюджета этим CLI не подтверждается. Каждый запуск CLI выполняет настоящий запрос и расходует бесплатную квоту. Результат может отличаться или завершиться ошибкой.

Проверить `metadata.mode=ai`, реальную модель, attempts, версии; `verified_trip_result=false`, budget_status и schedule_status равны unknown. Сверить ID и URL с каталогом. Ошибочный JSON должен вернуть INVALID_REQUEST без вызова API. Для проверки отсутствия ключа можно временно переименовать локальный `.env` при отсутствии GEMINI_API_KEY в окружении, запустить CLI и затем вернуть файл; ожидается MISSING_API_KEY и attempts=0. Квоту и 503 воспроизводят offline-тесты, специально исчерпывать лимит не нужно.
