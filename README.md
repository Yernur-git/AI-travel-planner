# AI Travel Planner

Учебный групповой проект: планирование поездки по Алматы на 1–3 дня по датам, интересам и общему бюджету в KZT. Планируемый результат — расписание, источники и оценка питания, местного транспорта и билетов. Проживание, дорога до Алматы, бронирование и оплата исключены. Карта и погода — дополнительные цели.

Текущая версия включает общую основу и отдельный локальный каталог первых 5 реальных мест с загрузкой и поиском. Streamlit по-прежнему показывает только учебный запрос/результат и не читает каталог. **Gemini не подключён. Демо не является AI-ответом, реальной рекомендацией или готовым checkpoint.** В демо источников и цен нет; реальные источники и ограничения каталога описаны отдельно в [data/README.md](data/README.md).

Gemini API free tier выбран; доступ, конкретная модель и квоты пока не проверены. Для разработки используется платный Codex. В демо ключ и аккаунт Gemini не нужны; сетевых вызовов к провайдеру нет.

## Установка на Windows PowerShell

Проверено на Python 3.11.9. Для такой же среды используйте Python 3.11; другие версии/ОС пока не проверены. Нужен доступ к пакетному индексу для установки зависимостей.

Откройте терминал в корне своей копии репозитория, где лежит app.py:

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Активация окружения не требуется, менять ExecutionPolicy не нужно. Если `python` не найден, установите Python 3.11 и перезапустите терминал. `requirements-dev.txt` включает зависимости приложения и pytest; для запуска без тестов достаточно `requirements.txt`. Прямые зависимости закреплены на проверенных версиях, транзитивные отдельно не заморожены.

## Запуск

```powershell
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address=127.0.0.1 --server.port=8501 --browser.gatherUsageStats=false
```

Откройте [локальное приложение](http://127.0.0.1:8501). Если порт занят, укажите другой свободный в `--server.port` и откройте соответствующий URL. Остановка — Ctrl+C в терминале сервера. При первом интерактивном старте Streamlit может запросить email: оставьте поле пустым, учётная запись для локального запуска не нужна.

## Ручная проверка

1. Убедитесь, что сверху видно «Демонстрационный режим. Gemini не подключён и не вызывается».
2. Посмотрите запрос: дата примера — завтра по времени Алматы, один человек, 10 000 KZT, интерес walking. Эти учебные значения заданы примером, а не введены пользователем.
3. Нажмите «Показать демонстрационный результат». Должны появиться условное место на 10:00–11:00 и явная пометка «не ответ Gemini».
4. Убедитесь, что расходы и часы неизвестны, источников 0. Известная часть 0 KZT не означает бесплатную поездку.
5. Откройте «Полный результат по контракту»: status=partial, metadata.mode=demo, metadata.model=null, attempts=0; total_estimate_kzt=null, budget_status=unknown, schedule_check.status=unknown, sources=[].

Формы произвольного запроса ещё нет: экран проверяет общую основу и формат, а не генерирует разные поездки. Демо не читает `.env` и после установки зависимостей не требует сети.

## Проверка моделей и экрана

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
```

Тесты проверяют 1–3 включительных дня, неверные даты/типы/интересы, неизвестные цены, структуру каталога, часовой пояс источника, ссылки ID, статусы ответа и кнопку Streamlit через AppTest. Они не проверяют факты об Алматы, Gemini, реальные часы работы или правильность будущего расчёта бюджета. Структурные модели не являются бизнес-валидаторами.

## Настройки и секреты

`.env.example` содержит только пустые GEMINI_API_KEY и GEMINI_MODEL для будущей части Ернура. Сейчас ничего заполнять не нужно. Если позже понадобится локальный `.env`, его можно создать копированием `.env.example`; файл игнорируется Git. Автозагрузка `.env` пока не реализована и не требуется демо. Будущая интеграция должна явно выбрать безопасное чтение переменных окружения.

Не добавляйте ключи в код, README, логи или историю Git. `.gitignore` исключает `.venv`, Python-кеши, `.env*` (кроме `.env.example`), Streamlit secrets и локальные результаты проверок.

## Разделение работы

| Область | Ответственный | Что ещё сделать |
| --- | --- | --- |
| `src/contracts/models.py` | Общая основа | Изменения формата согласовывать; спецификация в docs/CONTRACT.md |
| `src/demo.py` | Общая учебная фикстура | Держать отдельно от реального каталога и генерации |
| `src/catalog/`, `data/`; будущие `src/ai/`, `src/schedule/`, `eval/` | Ернур | Первые 5 мест и поиск готовы; расширение данных, Gemini, расписание, оценка AI открыты |
| `app.py`, будущие `src/ui/`, `src/budget/` и тесты бюджета | Рахат | Форма, все статусы, расчёты и тесты |
| Интеграция, зависимости и документы сдачи | Совместно | Проверить на обеих машинах и согласовать изменения |

Не созданы пустые реализации чужих модулей или имитация API. Следующая интеграционная граница: TripRequest → оркестратор Ернура → PlanDraft → проверки расписания и бюджета → TripResult → UI Рахата. Бизнес-вычисления и проверка реестров не включены в модели основы.

## Чего не хватает для checkpoint

- Проверить доступ и квоты выбранного Gemini free tier, выбрать доступную модель и выполнить настоящий вызов.
- Подготовить достаточный для первого сценария реальный каталог: места, URL, даты фактической проверки, часы, цены/явные неизвестные значения. Все примерно 25 мест — дальнейшая цель каталога, не обязательная предпосылка первого сценария.
- Реализовать содержательную AI-функцию: поиск по каталогу, составление плана и исправление по результатам проверок.
- Реализовать проверку расписания и переходов (Ернур), расчёт билетов, питания и транспорта с тестами (Рахат).
- Сделать форму реальных дат, интересов и бюджета, показать маршрут, связанные источники, расходы и понятные ошибки.
- Проверить хотя бы один реальный сквозной сценарий от формы до Gemini и проверенного результата, сохранить настоящую сессию/экспорт и ссылку на рабочий commit. Текущая задача не делает commit, push или merge.
- Подтвердить у преподавателя статус proposal/checkpoint и доступ к репозиторию; документы не подтверждают прохождение pass/fail.

Фиксированный набор 10 запросов, рубрика, baseline и измерение качества AI обязательны к итоговой сдаче и ещё не готовы. Демо и тесты моделей не заменяют evaluation. Официальные сроки и полный план — в PLAN.md; freeze — 13 декабря 2026 года.

## Компоненты и материалы

Собственная основа проекта использует [Streamlit](https://docs.streamlit.io/get-started/installation), [Pydantic](https://docs.pydantic.dev/latest/) и [pytest](https://docs.pytest.org/); tzdata предоставляет базу часовых поясов, необходимую ZoneInfo в том числе на Windows. Проверка экрана использует [Streamlit AppTest](https://docs.streamlit.io/develop/api-reference/app-testing/st.testing.v1.apptest). [Gemini API](https://ai.google.dev/gemini-api/docs/api-key) выбран для будущей интеграции, SDK ещё не установлен.

Демо написано для проверки формата и не использует реальные туристические данные. URL с доменом `.invalid` и даты в тесте Source — синтетические тестовые значения, не проверенные источники. Источники отдельного каталога, атрибуция, оценки, ограничения и открытые вопросы использования — в [data/README.md](data/README.md) и [data/sources.json](data/sources.json).

## Каталог Ернура без Gemini

`data/places.json` содержит 5 Place, `data/sources.json` — 13 Source с URL, checked_at и поддерживаемыми фактами. Общие модели не изменены. Поиск не составляет маршрут и не считает расходы; неизвестные часы/цены остаются неизвестными.

```powershell
.\.venv\Scripts\python.exe -m src.catalog --interest nature
.\.venv\Scripts\python.exe -m src.catalog --query Кастеева
.\.venv\Scripts\python.exe -m pytest tests/test_catalog.py -q
```

Python API: `from src.catalog import load_catalog`; затем `load_catalog().search(interests=['nature'])`. В результате — `places`, относящиеся к ним `sources`, `catalog_version`. Правила дат, инструкции добавления остальных мест и ограничения описаны в [руководстве каталога](data/README.md). Тесты работают без сети и проверяют структуру/поведение, а достоверность значений источников сверяется вручную.
